    - parse_sentiment(rows: list[dict]) -> list[dict]:
      * Takes list of GDELT article dicts, each with at minimum: "date" (YYYY-MM-DD str), "tone" (float), "num_articles" (int)
      * Returns list of dicts with keys: timestamp, source, topic, sentiment, volume, raw_text_sample
      * timestamp: from row["date"] formatted as "YYYY-MM-DDT00:00:00.000000Z"
      * source: always 'gdelt'
      * topic: always 'us_election_2024'
      * sentiment: row["tone"] as float
      * volume: row["num_articles"] as int
      * raw_text_sample: None (article text not stored in this pipeline)
      * This is the pure function tested by test_gdelt_sentiment_rows
    - fetch_daily_sentiment(date_str: str, keyword_query: str = "election usa 2024 trump harris") -> dict:
      * Queries GDELT DOC API for the given date (one day window)
      * Returns aggregated dict: {"date": "YYYY-MM-DD", "tone": avg_tone, "num_articles": count}
      * If API returns no articles: returns {"date": date_str, "tone": 0.0, "num_articles": 0}
    - ingest_gdelt(db_path: Path = DB_PATH, start: str = "2024-01-01", end: str = "2024-11-05") -> int:
      * Iterates over each day in [start, end] using pandas.date_range
      * For each day not already in sentiment_scores: calls fetch_daily_sentiment()
      * Uses tqdm for progress bar (multi-hour operation per RESEARCH.md)
      * Calls parse_sentiment() on result of each API call
      * INSERT OR IGNORE into sentiment_scores
      * Returns total rows inserted
      * Adds 0.2-second sleep between API calls to avoid rate limiting
    - No API key needed (GDELT is open) — do not prompt for credentials
    - Type hints, German docstrings, English comments
  </behavior>
